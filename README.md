# 🎙 AI 语音朗读 Web UI

一个基于 GPT-SoVITS TTS 服务的现代化网页界面，支持**弹幕朗读**与**长文有声书合成**。

纯前端单文件应用（HTML + CSS + JS），通过 REST API 对接任意 GPT-SoVITS 语音合成后端。

---

## ✨ 功能特性

### 🗨 弹幕朗读
- 输入文本，选择声音，一键合成并播放
- 支持**中英混合**输入
- 可选「说话人」前缀，自动拼接「xxx说」并缓存（同一观众多条弹幕只推理一次）

### 📖 长文合成（有声小说）
- 粘贴整章 / 整本文本（最多 10 万字），自动按句分段
- **多句一批并行合成**（默认 8 句一批，逐句返回音频），进度条按批推进
- 支持**断点续传**：合成中途崩溃，重启后从上次完成处继续
- **残片质检**：合成后按「每字时长（>0.62 s 可疑）+ 最长连续静音（>4 s 且占比
  >20%）」判一次，模型空转出来的半静音片段会被判废并自动重采；历史坏片可以用
  `repair_task.py <任务ID> <句号...>` 重新合成（长句自动按逗号拆段再拼回一个片段，
  句子数不变、点读索引不动）
- 任务结果**磁盘持久化 48 小时**，凭任务ID随时取回（任务ID 本身就是凭据）

### 🔤 符号朗读
语音前端会在归一化阶段**静默丢掉**念不出来的字符，正文里一旦出现就会缺字
（实测 `A+B=3` 读成 "A B three"）。所以送进后端之前先把符号换成读音：

| 原文 | 朗读 |
|---|---|
| `A+B=3` | A **加** B **等于** 三 |
| `50%` | 百分之五十（交给前端自己处理，不动） |
| `21℃` / `30°` | 二十一**摄氏度** / 三十**度** |
| `3~5 分钟` | 3 **到** 5 分钟（只在数字之间） |
| `C++` | C **加加** |
| `=====` / `----` / `***` | 装饰性分隔线，直接去掉不读 |

### 🔁 进度恢复
- 每个长文任务返回「任务ID」——它本身就是凭据，没有第二个字段
- 断网 / 刷新页面后，凭任务ID恢复进度并下载音频
- 12 小时内有效，过期自动清理

### 🎚 其他
- 语速调节（0.5x - 2.0x）
- 多个音色预设下拉切换
- 深色渐变现代界面

## 🖥 界面

单一页面（有声书合成 + 点读），不再包含弹幕朗读：

| 区域 | 用途 |
|------|------|
| **合成** | 整章文本 → 进度条 + 任务恢复，支持任务ID与上传存档文件 |
| **点读** | 按分割文件的句子列出全文，点击任意句跳转播放；可开启自动连读 |
| **存档** | 下载整章音频与分割文件（即服务端保存的那两个文件），清缓存后可传回 |

> 弹幕朗读接口 `POST /api/tts` 仍然保留，供 BeatSaber 等客户端直接调用；
> 只是不再出现在网页界面上。

### 📖 点读怎么工作

点读**不保存逐句音频**。整章音频就是各句音频的**直接拼接**（不掐头尾静音），
所以每句的起点就是时长累加，精确无误差：

```
starts[k] = sum(durations[:k])
```

**只需存 `starts`**：第 k 句的终点就是第 k+1 句的起点，最后一句直接播到文件末尾。
切割文件里存 `sents` / `starts` / `durations` / `audio_seconds`，
按 `starts[k] ~ starts[k+1]` 切出来的就是第 k 句本身的音频，无需任何换算。
点读就是在这一个音频文件上 seek：省磁盘、点击即响应。

只有**整段纯静音**的音频会被丢弃（`_is_silent_wav`）：单句合成返回静音时重试，
长文里反复失败的那一句会被跳过（该句时长为 0，占一个零长度区间，其余句子时间点不受影响）。

为此 `/api/tts/result` 支持 HTTP Range 请求——否则浏览器会认为音频不可跳转，
必须整章下载完才能定位。

### ⏳ 合成中提前点读（半成品音频）

点读不必等整章合成完。任务一提交，合成页就会出现
**「📖 一键发送到点读」**：点读页立刻用**已完成句子的拼接音频**当目标音频。

- **前缀音频**：服务端把已经合成好的句子拼成一个音频，它就是最终整章音频的
  **前缀**（逐样本一致），所以合成推进时**时间点一个都不用改**，只是换成同一份
  开头更长的音频；
- **未合成的句子**：在点读页里**划横线且不可点**，提示行显示「已就绪 k/n 句」；
- **读到进度末尾**：自动暂停等待，下一句合成出来就**自动接着读**；
- **合成完成**：自动换成完整音频，**当前位置 / 当前句 / 页码都不跳**；
- **下载按钮**在合成中禁用（分割文件只描述完整音频，半成品不能当存档）。

> 相关接口：`/api/tts/partial/{task_id}`（当前进度文档）与
> `/api/tts/partial/{task_id}/audio`（前缀音频，支持 `Range`）。
> 原有的 `/api/tts/split` 语义不变 —— 它始终只描述**完整**音频。

### 📱 点读界面

顶部两个标签页：**合成** / **点读**。点读是独立页面，铺满整个窗口——不是卡片里的一个小方框。
合成完成后（或导入任务后）会自动切到点读页。

| 功能 | 说明 |
|------|------|
| **翻页** | 句子按屏幕高度自动分页；`◀ 下一页 ▶` 或键盘 `←` `→` **水平翻页**（页面左右滑动，不滚动） |
| **点读** | 点击任意句子朗读该句；正在朗读的句子**带下划线**，页面自动跟随翻过去 |
| **自动连读** | 打开则逐句读下去；**关闭则每句播完即停**（不会一路读到章末） |
| **进度条** | 按**句子编号**计（正在朗读的句子，或当前页第一句） |
| **字号 / 颜色** | 14–30px 字号滑块 + 预设色板 / 取色器 |
| **背景图** | 自行上传，**铺满整个点读屏幕**：`cover` 等比例缩放、以图片中心对齐、不拉伸不留黑边；上面叠一层暗色蒙版保证文字可读 |
| **字体** | 自行上传 `.ttf / .otf / .woff2`，通过 FontFace 加载 |

外观设置都作用在阅读区容器上，所以每一页（以及分页测量用的隐藏探针）自动继承；
背景图作用在整个点读标签页上，因此工具栏和底栏也铺在图上（而不是只有正文那一条带）。
设置存在浏览器 localStorage 里（背景图/字体过大时自动降级为本次会话有效，
并给出提示，不会静默失败）。

### 💾 缓存清空后继续使用

服务端每个任务只存两个文件，**这两个文件就是存档**（没有额外打包格式）：

| 文件 | 内容 |
|------|------|
| `<任务ID>.wav` | 整章音频（各句拼接而成） |
| `<任务ID>.json` | 分割文件：句子列表、每句起点 `starts`、`durations`、音频总长 |

在网页上下载这两个文件，缓存被清空后原样传回即可：

- **音频 + 分割文件都传** → 直接复用音频，秒恢复，不重新合成；
- **只传分割文件** → 按同一套分句重新合成，句子边界完全一致；
- 若两个文件不是同一次合成的（音频长度对不上），会明确提示并改为按分割文件重新合成，
  避免点读跳到错的句子。

> 分割文件里**不含任何密钥**：任务ID 本身就是凭据 —— 没有任何接口能列出任务，
> `task_cache/` 也不对外暴露，所以知道 ID 就等于拿到这一章。

## 🧠 模型与并发池

`config_intel.yaml` 只定义一个模型 profile：`v5turbo`。所有音色（包括名字里带
`v4_` 的）都统一走 v5Turbo 底模 —— 前端即使传旧版本名 `v4` 也会被归一化到
这个唯一 profile，服务端不再加载任何 v4 模型。

顶层开关 `parallel_infer` 决定实例池策略：

| `parallel_infer` | 实例策略 | 实例内推理 | 显存 |
|---|---|---|---|
| `true`（默认） | **强制单实例**：无论请求什么版本都只用默认模型的 1 个实例（9880），其他模型 profile 全部忽略，绝不会因模型不同启动第二个实例 | **长文按 `parallel_batch_size` 句一批提交**（默认 8），后端 `/tts_batch` 一次前向解多句、逐句返回音频 | ~2.2 GiB |
| `false` | 每个模型 `ports_per_model` 个实例（当前 4 个：9880-9883）并发，仍按版本加载对应模型 | 串行 `batch_size=1` | 4 份 ~8.8 GiB + 激活 ≈ 12-13 GiB |

> 强制单实例是为了避免"模型不同启动第二个进程"导致的显存不足（OOM）。
> 打开此模式后前端传任何 `version` 都会被归一化到 `v5turbo`。

**长文为什么必须「多句一批」**：后端是单进程，`/tts` 的推理在事件循环里同步跑，
一句一请求时请求之间是严格串行的 —— 这时 `batch_size` 只会作用在"这一句被切成
几段"上，短句根本切不出第二段，看起来就像完全没并行。服务端现在把连续的几句
合成一次请求（`/tts_batch`），模型在同一批前向里解码，再按句把音频单独交回来，
点读的时间点不受影响。A770 实测：

| 一次提交 | 每句耗时 | 相对逐句 | 音质 |
|---|---|---|---|
| **1 句（默认，串行）** | **12.1 s** | **1.0×** | 基准 |
| 4 句 | 8.2 s | 1.5× | 轻微影响 |
| 8 句 | 5.6 s | 2.1× | **明显下降**（串句、尾音发虚）|
| 12 / 16 句 | 6.5 s | 1.9× | 更差，只增显存峰值 |

> 合批能省 30~45% 时间，但长文上音质损失可闻（8 句最明显，4 句也有轻微）
> —— 有声书是给人听几小时的，默认回到**逐句串行**（`parallel_batch_size: 1`）。
> 想提速可以调到 4；再往上不建议。

- 端口租约池保证同一端口不会被并发 POST；关闭并行时第 5 个请求会等待空闲实例
- `pool_idle_ttl: 0` → 实例加载完成后常驻，不因空闲卸载
- 冷启动仍按需触发、且加载过程全局串行，避免多进程同时加载造成显存峰值
- A770 为 15.56 GiB；若关闭并行并开满 4 实例，余量有限，**不要再增加实例数**
- 批量里个别句子抽到静音（采样随机）时，**只补那几句**逐句重试，其余照用；
  整批失败（老后端没有 `/tts_batch`、接口报错）才全部退回逐句
- 一次请求只能有一个 `text_lang`，所以只把**相邻的同语言句**并成一批
- **`dynamic_batch`（默认关）**：实验特性。后端某条序列 EOS 后把空出的槽位补下
  一句，并逐句流式回传，理论上能让第 1 句 19 s 内可听。**但实测在长任务上会死锁**
  ——AR 循环插入新序列后 tqdm 停住、句子不再 EOS，整条任务挂住（已复现两次）。
  稳定优先，默认关闭；打开前请先用短任务验证。
- 关闭时走「静态批」：一次提交 `parallel_batch_size`（4）句，整批返回后落盘。
  重跑 662 句的实测：批内不做长度约束（`parallel_batch_len_ratio: 1.0`）时批能
  凑满 4 句、约 10~15 s/句；若把长度约束设成 3 倍，662 句会被切成 268 批、其中
  93 批只有 1 句（等于退回串行）——小说正文里对话句和叙述句长度差经常超过 3 倍。
- 片段**按句子下标**存（流式的到达顺序是乱的：实测到达序 8,6,4,1,10,12…），
  最后按下标组装，所以谁先算完都不影响音频顺序；点读的 `starts` 是按
  `durations` 逐句累加的，顺序错一格就全乱

接口仍保留可选字段 `version`（为兼容旧前端），但只有 `v5turbo` 一个有效值：

```json
// POST /api/tts 或 /api/tts/long
{ "text": "...", "voice": "v4_sunflv", "version": "v5turbo", "speed": 1.0 }
```

`GET /api/voices` 的 `versions` 现在只返回 v5Turbo，`GET /api/health` 的 `pool`
会列出各端口的实时状态（cold/warming/hot）。

### 🖥 多服务器与模型能力

前端顶栏的服务器下拉由 `config_intel.yaml` 的 `servers:` 驱动，每台机器的
**音色与模型版本各自独立**。加机器只改配置：

```yaml
servers:
  - name: "本机 A770"
    url: ""                        # 空 = 同源
  - name: "9070XT"
    url: "http://other:8000"       # 内网 http 也行
forward_tls_verify: false          # 转发到自签名 https 时用（默认就关）
```

**所有请求都由本机服务端转发**，浏览器只跟本机说话：

```
浏览器 ──/api/voices?_srv=1──▶ 本机代理 ──/api/voices──▶ 9070XT
```

- 前端所有请求（含 `<audio src>`、EventSource）都发同源，带 `_srv=<下标>`
  （也可用请求头 `X-BSAI-Server`），由本机中间件转发到那台并流式回传
- 因此**不再有跨域，也不会有 https 页面里发 http 请求被浏览器拦掉的混合内容问题**
- `Range` 原样透传，几百 MB 的整章音频拖动进度条照常工作（实测返回 206 且字节一致）
- `/api/servers`、`/api/health` 永远由本机处理，不参与转发
- 远端连不上时返回 `502` 并带上原因，前端会提示「无法连接服务器「xxx」」

### ⏯ 任务控制：暂停 / 终止 / 重试

合成页进度条下方会按状态出现按钮：

| 状态 | 按钮 | 说明 |
|---|---|---|
| 合成中 | ⏸ 暂停 · ⏹ 终止 | 暂停在当前批结束后生效，片段与进度全部保留 |
| 已暂停 | ▶ 继续 · ⏹ 终止 | 继续 = 从断点续跑（可换服务器） |
| 失败 | 🔁 重试第 N 句起（服务器名）· 🗑 删除任务 | 重试沿用分句与已落盘片段 |

接口：

```
POST /api/tts/pause/{task_id}    # 批间停下，status → paused
POST /api/tts/stop/{task_id}     # 停止并删除片段/整章音频/任务记录
POST /api/tts/retry/{task_id}    # 从 done 续跑；带 _srv 时用那台合成
```

行为细节：

- 暂停/终止都在**批与批之间**检查（生产配置 `parallel_batch_size: 1`，
  所以最快每句一次；批越大生效越晚，长按暂停不会丢当前批的成果）
- 暂停是持久的：服务重启后仍是 `paused`，不会自己开跑，等你点「继续」
- 终止会删掉这条任务的全部产物（不可恢复），前端会二次确认
- 继续/重试用**当前选中的服务器** —— 实测本机合成到 1/5 暂停，切到 9070XT
  继续，3 秒跑完 5/5（注意：跨机器续跑会让同一章音色前后不同）

### 失败语义（重要）

以前某句合成失败会被「跳过并当作完成」——任务显示 100%，但点读指着一截不存在的
音频。现在：

- 单句重试（引擎模式 3 次、本机 10 次）后仍拿不到音频 → **整条任务标 `error`**，
  `done` 停在失败那句之前，错误信息里写明「第 N 句合成失败（原因）」
- 已落盘的前缀片段保留，点读仍可听已就绪部分，重试会从失败那句继续
- 引擎模式下建任务前先探活（`/healthz` `/health` `/api/health`，3 s），
  连不上直接 502，不会建一个注定失败的任务
- 前端轮询看到 `error` 会显示「❌ 合成失败: …」并停止，不再往下走

### ⚡ 借远端算力：`engine`

如果那台只跑着池 API（`/tts_batch`）而没有 bsai 代理，可以让本机把「合成」这一步
交出去 —— 分句、进度、点读时间轴、断点续传全部仍在本机，只有每一句的合成请求
发给远端。配置里加一段 `engine:` 即可：

```yaml
servers:
  - name: "本机 A770"
    url: ""
  - name: "9070XT"
    url: "http://streaming6.sunflv.top:9881"
    desc: "池 API（cuda×4）· 长文用它的算力"
    engine:
      api_key: "bsai-..."          # 远端池的 X-API-Key（没开鉴权可省略）
      default_voice: "sunflv_phone"
      voice_map:                   # 本机音色名 → 远端音色名
        v4_sunflv: sunflv_phone
```

行为：

- 前端下拉里显示 `⚡ 合成引擎`；选中后 `/api/voices` 仍转发到那台（看它有哪些音色）
- `/api/tts/long`、`/api/tts` 由**本机**处理，只是把每句/每批发到 `engine.url`
- 音色按 `voice_map` 改名；没配映射的走 `default_voice`；映射到的音色出静音时
  自动用 `default_voice` 重试一次（远端情绪参考音念中性短句容易变气声）
- 远端挂掉时返回 502，任务标 error，不会静默产出空音频
- 实测（本地 A770 vs 9070XT 池）：4 句长文 **3 s** 完成（本机约 40~60 s），
  单句 1.7 s（本机约 10 s）

**模型列表不是写死的**：服务端启动时会读

1. 后端根目录的 `BSAI_PATCH.json`（Patcher 装完补丁自动写的能力清单）
2. 后端自己的 `GPT_SoVITS/configs/tts_infer.yaml` 里真实存在的版本段

两者取交集，再和本机 `models:` 配置交叉，只对外宣称真正能跑的版本。
只装了 v4 的机器不会显示 v5turbo；完全没有交集时日志会告警，提示补丁没装好。

`/api/voices` 额外返回 `backend_capabilities`（如 `["v4","v5turbo"]`）和
`server_name`，前端会把它显示在音色下方。

## 🔌 对接的 API

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/voices` | 获取可用声音列表 |
| `POST` | `/api/tts` | 单句合成（弹幕/说话人前缀）→ `audio/wav` |
| `POST` | `/api/tts/long` | 提交长文任务 → `{task_id}` |
| `GET` | `/api/tts/progress/{task_id}` | 查询合成进度 |
| `GET` | `/api/tts/result/{task_id}` | 整章音频（支持 `Range`）→ `<任务ID>.wav` |
| `GET` | `/api/tts/split/{task_id}` | 分割文件 → `<任务ID>.json` |
| `GET` | `/api/tts/partial/{task_id}` | 点读「当前进度」文档（合成中=前缀时间点，完成后=最终文档）|
| `GET` | `/api/tts/partial/{task_id}/audio?v=k` | 已完成部分的前缀音频（支持 `Range`）|
| `POST` | `/api/tts/import` | multipart 上传 `split`(.json) + `audio`(.wav，可选) → 新任务 |

### 请求示例

```json
// POST /api/tts  （单句，弹幕客户端用）
{
  "speaker": "主播名",       // 可选，为空则只读文本
  "text": "欢迎来到直播间",
  "voice": "default",
  "speed": 1.0
}

// POST /api/tts/long  （长文）
{
  "text": "整章小说文本……",
  "voice": "default",
  "speed": 1.0
}
```

### 长文任务流程

```
POST /api/tts/long → {task_id}
    ↓ 轮询
GET /api/tts/progress/{task_id} → {status, done, total}
    ↓ 完成后（下载这两个文件即存档）
GET /api/tts/result/{task_id} → <任务ID>.wav  整章音频（Range 可跳转）
GET /api/tts/split/{task_id}  → <任务ID>.json 分割文件（点读偏移）
    ↓ 前端据此点读；清缓存后把这两个文件传回即可恢复
POST /api/tts/import  （multipart: split=.json, audio=.wav）→ 新 {task_id}
```

### 深链

`/?task=<任务ID>` 直接打开某任务的点读界面，可收藏/分享。
（旧链接里多出来的 `&key=<密钥>` 会被直接忽略，收藏夹里的地址照旧可用。）

## 🚀 部署

### 方式一：嵌入后端（推荐）

前端内嵌于 TTS 代理服务中，启动后直接访问根路径：

```bash
# 启动 TTS 后端 + 代理
./start_all.sh   # 或对应平台的启动脚本

# 打开浏览器
http://localhost:8000
```

### 方式二：独立静态部署

将 `index.html` 部署到任意静态服务器（Nginx / GitHub Pages / CDN），并配置前端中的 `API_BASE` 指向后端地址：

```js
// 在 index.html 中配置
const API_BASE = 'https://your-tts-server.example.com';
```

> 注意：若前后端不同源，需后端开启 CORS。
